Сеть без магии: Packet Lab.

Представь, что сеть — это система доставки. Пакеты — посылки, IP-адреса — адреса отправителя и получателя, порты — конкретные службы. Здесь можно смотреть, как устройства общаются, раскрывать детали пакетов и вводить команды в учебную консоль.

СИНТЕТИЧЕСКИЙ ТРАФИКIP · TCP · UDP · DNS · TLS · HTTPБЕЗ ПОДКЛЮЧЕНИЯ К СЕТИ
Важное ограничение. Эта лаборатория не перехватывает данные реальных людей, не определяет владельца произвольного IP и не блокирует адреса в операционной системе. Все адреса и команды работают только внутри симуляции. В реальности анализировать разрешается лишь тот трафик, на который у тебя есть полномочия; HTTPS обычно скрывает содержимое данных от наблюдателя сети.

Как читать фильтр

ip.addr == A показывает пакеты, где адрес A встречается с любой стороны. tcp.port == 443 ищет TCP-пакеты с портом 443. Фильтр только скрывает несовпадающие строки — он не удаляет пакеты из учебного набора.

i

Не путай корреляцию и доказательство. Один странный пакет ещё не доказывает атаку. Смотри на последовательность, объём, частоту, контекст устройства и события в других источниках.

ИНТЕРАКТИВНОЕ ОБЪЯСНЕНИЕ

DoS и DDoS: что происходит с сервисом?

DoS — отказ в обслуживании, когда доступность сервиса нарушается из-за исчерпания ресурсов или другого воздействия. DDoS — распределённый вариант: нагрузка приходит с множества источников. Важное отличие — распределение источников, а не просто «большое число пакетов». Симуляция ниже показывает только условную нагрузку и влияние на доступность; реальный трафик не отправляется.

01 / DO S

Один источник

При простой модели DoS избыточная нагрузка идёт от одного источника. В реальности источники могут подменяться или использовать несколько путей, поэтому одного IP недостаточно для диагноза.

Что проверять: частоту событий, тип ресурса, ошибки сервера, нормальную базовую нагрузку.
02 / DDoS

Много источников

При DDoS нагрузка распределена между несколькими устройствами или сетями. Блокировка одного адреса может почти ничего не изменить, а часть источников может быть обычными скомпрометированными устройствами.

Что проверять: всплеск объёма, распределение по адресам/сетям, запросам и протоколам, влияние на легитимных пользователей.
03 / DEFENSE

Как защищаются

Защита зависит от слоя и типа нагрузки: фильтрация и ограничение скорости, CDN/anti-DDoS провайдер, защита приложения, масштабирование, кэширование и план реагирования.

Аналитику важно зафиксировать время, масштаб, затронутые сервисы, признаки и эффективность мер по утверждённому плану.
ТЕОРИЯ С ПРИМЕРАМИ

Как читать сетевой пакет — с нуля

Пакет — это часть данных, передаваемая по сети. В анализаторе он показан как набор вложенных заголовков. Каждый уровень отвечает на свой вопрос: по какой локальной сети передали кадр, между какими IP-узлами идёт обмен, какой транспортный протокол используется и какое приложение общается.

EthernetСвязь внутри локального канала: MAC-адреса соседних сетевых устройств.
IPЛогический источник и назначение пакета между сетями.
TCP / UDPДоставка данных между программами через порты.
TLS / HTTP / DNSПротокол прикладного уровня, если его можно определить.
PayloadСодержимое. При HTTPS полезные данные обычно зашифрованы.
ПОНЯТИЕ 01

IP и порт — разные вещи

IP-адрес указывает на сетевой интерфейс или узел в контексте сети. Порт помогает операционной системе направить данные конкретной службе. Один узел может одновременно обслуживать HTTPS, DNS и другие сервисы.

Пример: 10.10.5.24:53023 → 10.10.5.80:443. Источник использует временный порт 53023, сервер принимает TCP-соединение на 443.
ПОНЯТИЕ 02

TCP и UDP

TCP устанавливает логическое соединение, нумерует байты и повторно передаёт потерянные данные. UDP не устанавливает такую сессию и имеет меньшие накладные расходы; порядок и повторная доставка обеспечиваются приложением, если нужны.

Не делай вывод по одному порту: DNS часто использует UDP/53, HTTPS — обычно TCP/443 либо QUIC поверх UDP/443.
ПОНЯТИЕ 03

DNS — имя в адрес

DNS позволяет приложениям находить IP-адреса и другие сведения по доменному имени. Запрос и ответ могут показать, к какому имени обращалось устройство, но сам по себе запрос не означает угрозу.

Ищи необычные домены, редкие запросы, ошибки ответа и большое количество запросов; сравнивай с обычным поведением устройства.

TCP handshake — как начинается соединение

Для стандартного установления TCP-соединения стороны обмениваются тремя сообщениями. Это не «три отдельных соединения», а шаги согласования состояния одного соединения.

1. SYN →Клиент просит начать соединение и сообщает начальный номер последовательности.
2. ← SYN, ACKСервер подтверждает запрос и предлагает свою начальную последовательность.
3. ACK →Клиент подтверждает ответ; после этого соединение обычно готово к передаче данных.
Практический смысл: большое число SYN без соответствующих завершённых рукопожатий может быть поводом для проверки, но возможны и сетевые потери, сканирование, асимметричная маршрутизация или неполный захват. Нужны временной контекст и другие признаки.

Что шифрование меняет для аналитика?

При обычном HTTP в захвате могут быть видны содержимое запросов и ответы. HTTPS использует TLS для защиты содержимого. Даже при шифровании могут остаться метаданные: IP-адреса, порты, время, размеры пакетов и часть сведений об установлении соединения. Поэтому анализатор помогает понять структуру коммуникации, но обычно не раскрывает секретное содержимое HTTPS без предусмотренного и разрешённого доступа к расшифрованным данным.

Что изучить дальше

Симулятор поддерживает только небольшой набор выражений для обучения. Настоящий Wireshark имеет значительно больше полей и фильтров — команды ниже приведены как отправная точка, а полная грамматика доступна в официальной документации.

Фильтры для старта

tcp.port == 443 — TCP с портом 443.
